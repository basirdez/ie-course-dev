# تمرین ۰: جعبه‌ابزار و اولین ردپا

> جلسهٔ صفر · قبول یا رد · پیش‌نیاز همهٔ تمرین‌ها · مهلت: شب پیش از جلسهٔ ۱

## هدف

ابزارهای درس را آماده کنید، مخزن تحویل را بسازید، و اولین بار ببینید یک درخواست به یک سایت از چه مرحله‌هایی می‌گذرد و هر مرحله چقدر طول می‌کشد. همین مرحله‌ها موضوع جلسهٔ ۱ است.

## پیش‌بینی (سر کلاس نوشتید؛ همان را در README بیاورید)

در اولین اجرای `curl` به یک سایت، کدام مرحله بیشترین زمان را می‌گیرد: پیدا کردن نشانی (DNS)، برقراری اتصال، راه‌اندازی TLS، یا انتظار برای اولین بایت پاسخ؟ در اجرای دوم چه چیزی عوض می‌شود؟

## کار پایه

۱. این ابزارها را نصب کنید و نسخه‌شان را در `evidence/versions.txt` بنویسید: git و curl (نسخهٔ ۸ یا بالاتر؛ در Windows همان `curl.exe`) و Node 22 یا Python 3.11 و `dig` (در Windows: `Resolve-DnsName` در PowerShell).

۲. مخزن خصوصی `ie1405-` و شمارهٔ دانشجویی (مثلاً `ie1405-401234567`) را بسازید، حساب دستیار آموزشی را دعوت کنید، و پوشهٔ `ex00` را با ساختار [قواعد درس](../../course-policy.md) بسازید.

۳. سه سایت انتخاب کنید (یکی ایرانی، مثلاً `scu.ac.ir`). برای هرکدام این دستور را **دو بار پشت‌سرهم** اجرا کنید و خروجی را در `evidence/timings.txt` نگه دارید:

```sh
curl -s -o /dev/null -w "dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first-byte=%{time_starttransfer} total=%{time_total}\n" https://scu.ac.ir/
```

در Windows به‌جای `/dev/null` بنویسید `NUL`. عددها ثانیه و **تجمعی**‌اند: زمان TLS برابر `tls` منهای `connect` است.

۴. برای هر سایت رکوردهای A و AAAA را بپرسید (`dig A scu.ac.ir` و `dig AAAA scu.ac.ir`) و در `evidence/dns.txt` بگذارید.

## چالش

- جدولی بسازید که سهم هر مرحله را برای هر سایت نشان دهد، و بگویید پیش‌بینی‌تان کجا درست بود و کجا نه.
- اگر زمان DNS در اجرای دوم کم شد، پاسخ از کجا آمد؟ curl بین دو اجرا چیزی نگه نمی‌دارد؛ پس cache کجاست؟
- اتصال خود شما IPv6 دارد؟ (`curl -6 https://www.google.com` را امتحان کنید.) اگر ندارد، با الگوهای جلسهٔ صفر توضیح دهید چرا پروتکلی با بیش از ۲۵ سال عمر هنوز همه‌جا نیست.

## تصمیم مهندسی

فرض کنید سایتی دارید که کاربرانش بیشتر با گوشی و از شبکهٔ همراه می‌آیند. با این عددها، بهبود کدام مرحله بیشترین اثر را دارد؟ یک پاراگراف.

## پل به جلسهٔ ۱

عددهایی که گرفتید دقیقاً همان مرحله‌های جلسهٔ ۱ است: parse و DNS و اتصال و TLS و HTTP. در جلسه دوباره سراغشان می‌رویم.
