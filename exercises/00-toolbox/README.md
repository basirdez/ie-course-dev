# تمرین کوتاه ۰: یک درخواست کجا وقت می‌گذراند؟

> جلسهٔ صفر · تحویل: `short/s00.md` · مهلت: ساعت ۲۳:۵۹ شب پیش از جلسهٔ ۱

## هدف

ببینید یک درخواست به یک سایت از چه مرحله‌هایی می‌گذرد و هر مرحله چقدر طول می‌کشد. همین مرحله‌ها موضوع جلسهٔ ۱ است. این تمرین یک راه‌اندازی هم دارد که فقط همین یک بار لازم است.

## پیش‌بینی (سر کلاس نوشتید؛ همان را در فایل بیاورید)

در اولین درخواست به یک سایت، کدام مرحله بیشترین زمان را می‌گیرد: پیدا کردن نشانی (DNS)، برقراری اتصال، راه‌اندازی TLS، یا انتظار برای اولین بایت پاسخ؟ در درخواست دوم چه چیزی عوض می‌شود؟

## راه‌اندازی (یک بار)

۱. این ابزارها را نصب کنید: git، و curl نسخهٔ ۸ یا بالاتر (در Windows همان `curl.exe`)، و Node 22 یا Python 3.11.

۲. مخزن خصوصی `ie1405-` و شمارهٔ دانشجویی (مثلاً `ie1405-401234567`) را بسازید، حساب دستیار آموزشی را دعوت کنید، و فایل `short/s00.md` را با قالب [قواعد درس](../../course-policy.md) بسازید.

## آزمایش (حداکثر ۳۰ دقیقه)

دو سایت انتخاب کنید که یکی‌شان ایرانی باشد (مثلاً `scu.ac.ir`). برای هرکدام این دستور را **دو بار پشت‌سرهم** اجرا کنید:

```sh
curl -s -o /dev/null -w "dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first-byte=%{time_starttransfer} total=%{time_total}\n" https://scu.ac.ir/
```

در Windows، در PowerShell به‌جای `curl` بنویسید `curl.exe` و به‌جای `/dev/null` بنویسید `NUL`.

عددها ثانیه و **تجمعی**‌اند: زمان TLS برابر `tls` منهای `connect` است، نه خود `tls`.

در بخش «شواهد» فایل، خط اول `curl --version` و چهار خط خروجی بالا را بگذارید.

## پل به جلسهٔ ۱

اگر زمان DNS در اجرای دوم کم شد، پاسخ از کجا آمد؟ curl بین دو اجرا چیزی نگه نمی‌دارد. جلسهٔ ۱ همین مرحله‌ها را یکی‌یکی باز می‌کند: parse و DNS و اتصال و TLS و HTTP.
