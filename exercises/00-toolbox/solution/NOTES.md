# یادداشت تصحیح تمرین ۰ (خصوصی)

- قبول: مخزن خصوصی با دسترسی دستیار، `versions.txt`، دو اجرای `curl` برای سه سایت، و `deps.txt` با خروجی خام `dig NS` و مالک IP و صادرکنندهٔ گواهی.
- نکتهٔ چالش DNS: curl هر بار resolver سیستم را صدا می‌زند؛ کاهش زمان در اجرای دوم از cache سیستم‌عامل (مثلاً systemd-resolved یا DNS Client در Windows) یا cache resolver ISP است.
- نکتهٔ رایج اشتباه: عددهای `-w` تجمعی‌اند؛ دانشجویی که `tls` را زمان TLS بداند، سهم TLS را بیش از حد می‌بیند.
- نکتهٔ اعتبار: اگر `ip=` یا زمان اتصال برای سایت ایرانی عجیب است (مثلاً RTT بیش از ۱۰۰ میلی‌ثانیه به سروری در ایران)، احتمالاً VPN روشن بوده است؛ README باید آن را اعلام کرده باشد.
- نقشهٔ وابستگی: پاسخ درست به شواهد خود دانشجو بسته است، نه به یک جدول ثابت. معیار: هر ادعا (ارائه‌دهندهٔ DNS، مالک IP، CA) به خطی از `evidence/` ارجاع دارد. نشانی `ip=` ممکن است لبهٔ یک CDN باشد، نه سرور اصلی؛ دانشجویی که این را تشخیص دهد، استدلال خوبی کرده است.
- پیچش: وابستگی‌های پنهان مثل اسکریپت یا فونت از دامنهٔ دیگر، API پرداخت، یا سرویس ایمیل با این ابزارها دیده نمی‌شوند؛ راه دیدنشان زبانهٔ Network در DevTools است (جلسهٔ ۱).
- تصمیم DNS: پاسخ خوب هر دو طرف را می‌بیند؛ دو ارائه‌دهنده در قطعی یکی کار را نگه می‌دارد، ولی هم‌گام نگه داشتن رکوردها و DNSSEC پیچیده‌تر می‌شود. پاسخ یک‌طرفه بدون هزینه، کامل نیست.
- در شبکه‌های همراه معمولاً اتصال و TLS سهم بزرگ‌تری دارند (RTT بالا)؛ کم کردن رفت‌وبرگشت (استفادهٔ دوباره از اتصال، TLS 1.3، HTTP/3) در جلسهٔ ۴ می‌آید.
- `[بررسی‌نشده: اجرای واقعی]` این نسخه از شبکهٔ ایران اجرا نشده است؛ پیش از انتشار، مدرس دستورها را برای `scu.ac.ir` از شبکهٔ دانشگاه اجرا کند و خروجی را در اسلاید پشتیبان جلسهٔ ۰ بگذارد.
