# تمرین ۱: کدام URL شما را گول می‌زند؟

> جلسهٔ ۱ · مهلت: شب پیش از جلسهٔ ۲

## سناریو

سرویس شما پیش‌نمایش لینک می‌سازد: کاربر یک URL می‌دهد و سرور آن را باز می‌کند. برای امنیت، فقط باید به `example.com` درخواست بفرستد. همکارتان این بررسی را نوشته است:

```js
if (!url.includes('example.com')) throw new Error('فقط example.com')
```

## پیش‌بینی (سر کلاس نوشتید؛ همان را در README بیاورید)

برای `http://evil.test\@example.com/`، مرورگر به کدام host وصل می‌شود؟ curl چطور؟

## کار پایه

برای هر یک از این هشت URL، **پیش از اجرا** جدولی پر کنید: host مقصد، path ارسالی، و origin.

```text
1  https://example.com@evil.test/login
2  http://evil.test\@example.com/
3  http://EXAMPLE.com:80/a/./b/../c
4  http://example.com./
5  http://example.com:0080/
6  http://[0:0::1]:8080/x
7  http://2130706433/
8  http://example.com/%2e%2e/admin
```

بعد پیش‌بینی را با دو parser بسنجید و خروجی خام را در `evidence/` نگه دارید:

- برای parser مرورگر: `node -e "const u=new URL(process.argv[1]); console.log(u.host, u.pathname, u.origin)" '<URL>'`
- برای curl: یک سرور محلی روی پورت 8080 بالا بیاورید (مثلاً `python3 -m http.server 8080`) و درخواست را به آن برگردانید تا خط درخواست و `Host` را ببینید:

```sh
curl -sv --connect-to ::127.0.0.1:8080 'http://evil.test\@example.com/' -o /dev/null
```

گزینهٔ `--connect-to` فقط مقصد TCP را عوض می‌کند؛ خط درخواست و `Host` همان است که curl از URL فهمیده است.

## چالش

- کدام URLها از بررسی `includes` بالا رد می‌شوند ولی درخواست را به جای دیگری جز `example.com` می‌فرستند؟
- دست‌کم دو URL پیدا کنید که curl و parser مرورگر آن‌ها را متفاوت می‌فهمند. اگر بررسی را با یکی انجام دهید و درخواست را با دیگری بفرستید، چه می‌شود؟
- بررسی درست را بنویسید (در زبان دلخواه) و نشان دهید هر هشت URL را درست رد یا قبول می‌کند.

## امتیازی

به یکی از URLهایی که به `127.0.0.1` می‌رسند فکر کنید: اگر روی همان سرور سرویسی فقط برای درون ماشین در حال اجرا باشد، مهاجم چه به دست می‌آورد؟ دنبال واژهٔ SSRF بگردید.

## تصمیم مهندسی

بررسی را با کدام parser انجام می‌دهید و چرا؟ در یک پاراگراف بگویید «یک بار parse کن و از همان نتیجه هم برای بررسی و هم برای ارسال استفاده کن» در این سناریو چه معنایی دارد.

## پل به جلسهٔ ۲

خط `GET /… HTTP/1.1` و فیلد `Host` که در خروجی curl دیدید، اولین خط‌های یک پیام HTTP‌اند. جلسهٔ ۲ همین پیام را کالبدشکافی می‌کند.
