# دموهای جلسهٔ ۶

> اجراشده با Node 22.22 و curl 8.5.0 و OpenSSL 3.0 روی Linux. خروجی‌ها در اسلایدهای پشتیبان دک آمده است.

```sh
node server.mjs        # http://127.0.0.1:8801     /poll  /longpoll  /events  /ws
```

سرور هر ثانیه یک خبر می‌سازد (`INTERVAL` به میلی‌ثانیه) و همان خبر را از چهار راه می‌رساند. بخش WebSocket بدون کتابخانه نوشته شده و فقط پیام متنی کوتاه‌تر از ۱۲۶ بایت را می‌فهمد؛ برای دیدن بایت‌ها کافی است، نه برای کار واقعی.

## دموی sse: یک پاسخ که تمام نمی‌شود

```sh
curl -sN http://127.0.0.1:8801/events
curl -sN -H 'Last-Event-ID: 2' http://127.0.0.1:8801/events
ORIGIN_PORT=8801 node ../05-intermediaries/proxy.mjs
curl -sN -m 4 http://127.0.0.1:8790/events ; echo "exit=$?"
```

- مشاهده: اول `retry: 2000`، بعد هر ثانیه یک بلوک `id` و `event` و `data`. با `Last-Event-ID: 2` خبرهای ۳ تا آخر یک‌جا می‌رسند و بعد جریان ادامه پیدا می‌کند.
- از پشت proxy جلسهٔ ۵، در چهار ثانیه هیچ بایتی نمی‌رسد و curl با کد ۲۸ (پایان مهلت) بیرون می‌آید. درخواست WebSocket هم از پشت همین proxy شکست می‌خورد.
- دام: بدون گزینهٔ `-N`، خود curl خروجی را جمع می‌کند و به نظر می‌رسد سرور کُند است.
- دام: اگر در محیط شما متغیر `HTTP_PROXY` تنظیم است، `--noproxy '*'` را بیفزایید.

## دموی ws: handshake و frame با دست

```sh
printf '%s' 'dGhlIHNhbXBsZSBub25jZQ==258EAFA5-E914-47DA-95CA-C5AB0DC85B11' | openssl sha1 -binary | base64
MASK=37fa213d node wsclient.mjs Hello
```

- مشاهده: خروجی `openssl` برابر `s3pPLMBiTxaQ9kYGzzhZRbK+xOo=` است؛ همان مقداری که در مثال RFC 6455 آمده.
- کلاینت این frame را می‌فرستد: `81 85 37 fa 21 3d 7f 9f 4d 51 58`. سرور این دو را برمی‌گرداند: `81 05 48 65 6c 6c 6f` و `81 0b 65 63 68 6f 3a 20 48 65 6c 6c 6f`.
- با `CHECK_ORIGIN=http://127.0.0.1:8801 node server.mjs` سرور handshake با `Origin` دیگر را با `403` رد می‌کند؛ برای اسلاید «SOP اینجا نیست».

## اندازه‌گیری: هر خبر چند بایت

با `curl -w '%{size_request} %{size_header} %{size_download}'` روی HTTP/1.1 اندازه گرفته شده است:

| سازوکار | یک‌باره | هر خبر | هر بار «خبری نیست» |
| --- | --- | --- | --- |
| polling | — | ۳۱۶ بایت (۸۹ درخواست، ۱۸۸ سرآیند پاسخ، ۳۹ بدنه) | ۲۸۱ بایت |
| SSE | ۲۹۵ بایت (۸۳ درخواست، ۲۱۲ سرآیند پاسخ) | ۴۴ بایت | صفر |
| WebSocket | حدود ۳۰۰ بایت handshake | ۲۱ بایت (۲ بایت سربار، ۱۹ بایت متن) | صفر |

عدد SSE سربار chunk در HTTP/1.1 را ندارد (حدود ۶ بایت برای هر خبر).
